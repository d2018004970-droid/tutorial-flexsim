1 Como o site é gerado

Atualização (21/09/2026) O Word-Mestre não existe mais como arquivo de edição. Agora você edita Word_Mestre.md — um arquivo de texto simples, aberto no VS Code (ou qualquer editor de texto) — sem precisar do Word aberto em paralelo. Os mesmos marcadores entre colchetes continuam funcionando exatamente igual.

Um script (build/build.ps1) lê o Word_Mestre.md diretamente e monta os dados do site de forma mecânica — a mesma entrada sempre produz a mesma saída.

Editar Word_Mestre.md no VS Code→ Salvar→ Duplo clique em Gerar_Site.bat→ Ler relatorio-build.txt→ Abrir/recarregar index.html

O index.html, o CSS e o JavaScript do site nunca mudam quando você edita o conteúdo — só o arquivo de dados (assets/js/content.js) é regenerado.

Como o Markdown é estruturado

Cada Aula vira uma linha começando com ##, cada Modelo uma linha começando com ###. O resto (etapas, colunas, campos) é exatamente igual ao que você já digitava, só que sem o Word por trás:

No Word (antigo)No Markdown (agora)
Estilo de título "Título 2" na linha da Aula## 1) Aula 01
Estilo de título "Título 3" na linha do Modelo### 1.1) Modelo 01
Texto em negrito selecionado no Word<b>texto</b> (o VS Code mostra isso destacado)
Todo o resto ([ETAPA], [COLUNA], [PRINT]...)Idêntico, sem mudança nenhuma
Quer ver o conteúdo "bonito"? Toda vez que você roda o Gerar_Site.bat, ele também gera Word_Mestre_Visualizacao.docx — um Word de somente leitura, com títulos coloridos e negrito, montado automaticamente a partir do Word_Mestre.md. É só para conferir visualmente; edições feitas nele são perdidas na próxima geração (o arquivo que vale é sempre o .md).
Não delete build/modelo_estilos.docx — é o "molde" de onde o site copia as fontes/cores dos títulos para montar o Word de visualização.

3 O que o conversor tolera (e avisa)

O script não trava o site por um marcador fora do lugar — ele sempre tenta gerar algo razoável e registra um aviso no relatório. Isso é o que muda em relação a antes.

  • Marcador desconhecido (ex.: [Run Time] antes de entrar na tabela): vira uma propriedade genérica com esse nome. Nada é perdido, nada quebra.
  • [TITULO] sem [COLUNA] antes: uma coluna é criada automaticamente.
  • Print referenciado que não existe em images/: vira um aviso — o card daquela imagem simplesmente não aparece, o resto da etapa segue normal.
  • Posição sem prefixo de nome, com mais de um objeto citado: o script tenta resolver pela ordem em que os objetos foram citados; quando não consegue com segurança, avisa qual nome escolheu.
DicaDepois de editar o Word, sempre dê uma olhada rápida em build/relatorio-build.txt. Zero avisos novos = pode confiar no site.

4 Convenção para o mini-mapa (importante)

O mini-mapa de cada modelo é desenhado automaticamente a partir das coordenadas que você já escreve em [VISUALS]/[DECISION_POINT]/[CONVEYOR]. Para isso funcionar bem:

  • Sempre que citar coordenadas de mais de um objeto na mesma propriedade, prefira o formato NOME: X = .. ; Y = .. (nome antes dos dois-pontos) em vez de deixar os objetos "soltos" um embaixo do outro. Isso evita ambiguidade.
  • Sempre que reposicionar um objeto que já existia em um modelo anterior (ex.: mover o Sink de lugar), inclua um bloco [VISUALS] com a nova coordenada — não basta escrever "coloque em X = 50" só no Roteiro ou na Observação. O mini-mapa só lê coordenadas de dentro de [VISUALS]/[DECISION_POINT], então uma reposição mencionada apenas em texto livre não é capturada, e o objeto continua aparecendo na posição antiga no mapa.
Situação encontradaIsso já aconteceu com o Sink "SAIDA_CLIENTES": a reposição para X=50 (Modelo 03) e X=80 (Modelo 05) está apenas em texto corrido, então o mini-mapa desses modelos ainda mostra o Sink na posição original (X=30). Veja a seção 7 ("Ainda precisam da sua ação").

5 Marcadores opcionais novos sugestão, não obrigatório

O site (renderer) já sabe exibir estes três marcadores como caixas de destaque, caso você queira usá-los no futuro. Eles são opcionais — nenhuma etapa existente precisa deles.

MarcadorUso sugerido
[DICA]texto[FIM_DICA]Uma dica rápida, não essencial ao procedimento.
[ATENCAO]texto[FIM_ATENCAO]Um alerta mais forte que uma Observação comum.
[ATALHO]texto[FIM_ATALHO]Destaca um atalho de teclado citado no meio do texto.

6 Como ler o relatório de geração

build/relatorio-build.txt é gerado a cada execução do Gerar_Site.bat e traz:

  • Contagem de aulas, modelos, etapas, colunas e prints — útil para conferir que nada "sumiu".
  • Lista de avisos, cada um dizendo em qual Modelo/Etapa ocorreu.
  • Quantas imagens foram otimizadas nessa execução (a otimização só roda de novo quando o print original muda).
