1 Como o site é gerado

Atualização (21/09/2026) O Word-Mestre não existe mais como arquivo de edição. Agora você edita Word_Mestre.md — um arquivo de texto simples, aberto no VS Code (ou qualquer editor de texto) — sem precisar do Word aberto em paralelo. Os mesmos marcadores entre colchetes continuam funcionando exatamente igual.

Um script (build/build.ps1) lê o Word_Mestre.md diretamente e monta os dados do site de forma mecânica — a mesma entrada sempre produz a mesma saída.

Editar Word_Mestre.md no VS Code→ Salvar→ Duplo clique em Gerar_Site.bat→ Ler relatorio-build.txt→ Abrir/recarregar index.html

O index.html, o CSS e o JavaScript do site nunca mudam quando você edita o conteúdo — só o arquivo de dados (assets/js/content.js) é regenerado.

Como o Markdown é estruturado

Cada Aula vira uma linha começando com ##, cada Modelo uma linha começando com ###. O resto (etapas, colunas, campos) é exatamente igual ao que você já digitava, só que sem o Word por trás:

No Word (antigo)No Markdown (agora)
Estilo de título "Título 2" na linha da Aula## 1) Aula 01
Estilo de título "Título 3" na linha do Modelo### 1.1) Modelo 01
Texto em negrito selecionado no Word<b>texto</b> (o VS Code mostra isso destacado)
Todo o resto ([ETAPA], [COLUNA], [PRINT]...)Idêntico, sem mudança nenhuma
Quer ver o conteúdo "bonito"? Toda vez que você roda o Gerar_Site.bat, ele também gera Word_Mestre_Visualizacao.docx — um Word de somente leitura, com títulos coloridos e negrito, montado automaticamente a partir do Word_Mestre.md. É só para conferir visualmente; edições feitas nele são perdidas na próxima geração (o arquivo que vale é sempre o .md).
Não delete build/modelo_estilos.docx — é o "molde" de onde o site copia as fontes/cores dos títulos para montar o Word de visualização.

3 O que o conversor tolera (e avisa)

O script não trava o site por um marcador fora do lugar — ele sempre tenta gerar algo razoável e registra um aviso no relatório. Isso é o que muda em relação a antes.

  • Marcador desconhecido (ex.: [Run Time] antes de entrar na tabela): vira uma propriedade genérica com esse nome. Nada é perdido, nada quebra.
  • [TITULO] sem [COLUNA] antes: uma coluna é criada automaticamente.
  • Print referenciado que não existe em images/: vira um aviso — o card daquela imagem simplesmente não aparece, o resto da etapa segue normal.
  • Print que está em images/ mas não foi citado no Word_Mestre.md: vira um aviso ("Print na pasta images/ que nao esta no Word_Mestre.md"). Só confere arquivos com nome no padrão AULAX_MODELOY_...; ícones como down_arrow.bmp ficam de fora.
  • Posição sem prefixo de nome, com mais de um objeto citado: o script tenta resolver pela ordem em que os objetos foram citados; quando não consegue com segurança, avisa qual nome escolheu.
DicaDepois de editar o Word, sempre dê uma olhada rápida em build/relatorio-build.txt. Zero avisos novos = pode confiar no site.

4 Convenção para o mini-mapa (importante)

O mini-mapa de cada modelo é desenhado automaticamente a partir das coordenadas que você já escreve em [VISUALS]/[DECISION_POINT]/[CONVEYOR]. Para isso funcionar bem:

  • Sempre que citar coordenadas de mais de um objeto na mesma propriedade, coloque o nome antes da coordenada — "NOME" - [Mid6_small.png] X = .. ; Y = .. (com aspas) ou NOME: X = .. ; Y = .. — em vez de deixar os objetos "soltos" um embaixo do outro. Isso evita ambiguidade.
  • Sempre que reposicionar um objeto que já existia em um modelo anterior (ex.: mover o Sink de lugar), inclua um bloco [VISUALS] com a nova coordenada — não basta escrever "coloque em X = 50" só no Roteiro ou na Observação. O mini-mapa só lê coordenadas de dentro de [VISUALS]/[DECISION_POINT], então uma reposição mencionada apenas em texto livre não é capturada, e o objeto continua aparecendo na posição antiga no mapa.

Mini-mapa em escala: posição, rotação e tamanho

O mini-mapa desenha cada objeto com o tamanho real (X × Y, em metros) e a rotação do FlexSim, na mesma escala em X e Y. Dentro do [VISUALS], cada linha é reconhecida pelo ícone, igual ao Quick Properties do FlexSim:

Ícone na linhaSignificaExemplo
[Mid6_small.png]Posição (o centro do objeto)"FILA" - [Mid6_small.png] X = 20.00 ; Y = 0.00 ; Z = 0.00
[rotate_arrow.png]Rotação em Z (graus)"ATENDENTE" - [rotate_arrow.png] Z = 270.00
[_resize.png] ou [resize.png]Tamanho (X × Y × Z)"PALLETS_FINALIZADOS" - [_resize.png] X = 25.00 ; Y = 1.50
  • Tamanho só para objetos redimensionados. Os demais usam automaticamente o tamanho padrão do tipo (o que o FlexSim mostra num objeto recém-inserido): Source 1,06 × 1,06 · Queue 2 × 2 · Processor 4 × 3 · MultiProcessor 5 × 3,08 · Combiner/Separator 4,02 × 3,01 · Sink 1,06 × 1,06 · Operator 0,4 × 0,58 · Rack 20 × 1,5 · Location Kiosk 0,36 × 0,58 · Location Registration 2 × 2. NetworkNode e Decision Point são pontos e aparecem com um tamanho mínimo.
  • Escreva o tamanho como o Quick Properties mostra, sem trocar X por Y por causa da rotação — o site gira o desenho sozinho (ex.: o Rack de 25 × 1,5 girado 270° aparece na vertical).
  • Mover um objeto não desfaz a rotação nem o tamanho que ele já tinha.
  • Exceção: dentro do [DECISION_POINT], o [_resize.png] continua sendo lido como posição (é assim que os Decision Points dos Modelos 03 e 04 estão escritos).
  • Objetos muito pequenos (Operator, NetworkNode…) aparecem com um tamanho mínimo na tela, para continuar visíveis e clicáveis. Passe o mouse sobre um objeto para ver nome, posição, tamanho e rotação.

Renomear um objeto

Se um objeto citado no [OBJETO] é renomeado na mesma coluna, escreva o novo nome no [NOME]/[NAME] com o tipo na frente — o nome antigo sai do mini-mapa (senão ele vira um objeto "fantasma") e o novo herda a posição. Os nomes são casados pelo tipo, na ordem:

[OBJETO]
Processor - "TESTE"
Operator - "OPERADOR_TESTE"
[PROPERTIES]
[NAME]
Operator - "OPERADOR_TESTE_1"
Processor - "TESTE_1"

Remover um objeto

Quando um objeto é apagado do modelo, liste-o no [OBJETO] com (REMOVIDO) no fim da linha — ele some do mini-mapa a partir daquela etapa (os modelos anteriores continuam mostrando-o):

[OBJETO]
Operator - "MOVIMENTADOR_1" (REMOVIDO)
Operator - "MOVIMENTADOR_2" (REMOVIDO)

Aulas Extras têm mapa próprio

Aulas numeradas a partir de 90 (ex.: ## 90) Aula 90 - Extra...) são modelos independentes da fábrica dos Modelos 01–11: o mini-mapa delas começa vazio e nada delas aparece nas aulas normais (nem o contrário). Por isso o Modelo 90 pode ter um Sink SAIDA_CLIENTES próprio sem afetar o Sink SAIDAS_CLIENTES da fábrica.

5 Marcadores opcionais novos sugestão, não obrigatório

O site (renderer) já sabe exibir estes três marcadores como caixas de destaque, caso você queira usá-los no futuro. Eles são opcionais — nenhuma etapa existente precisa deles.

MarcadorUso sugerido
[DICA]texto[FIM_DICA]Uma dica rápida, não essencial ao procedimento.
[ATENCAO]texto[FIM_ATENCAO]Um alerta mais forte que uma Observação comum.
[ATALHO]texto[FIM_ATALHO]Destaca um atalho de teclado citado no meio do texto.

6 Como ler o relatório de geração

build/relatorio-build.txt é gerado a cada execução do Gerar_Site.bat e traz:

  • Contagem de aulas, modelos, etapas, colunas e prints — útil para conferir que nada "sumiu".
  • Lista de avisos, cada um dizendo em qual Modelo/Etapa ocorreu.
  • Quantas imagens foram otimizadas nessa execução (a otimização só roda de novo quando o print original muda).

8 Arquivos para download (roteiros, Excel, .skp...)

Os arquivos ficam na pasta downloads/ do projeto (junto de index.html) e vão para o GitHub junto com o resto (Commit + Push). O site monta os botões sozinho ao rodar o Gerar_Site.bat.

1) Roteiro de cada modelo

Coloque o arquivo em downloads/roteiros/ com Modelo N em qualquer parte do nome (ex.: ROTEIRO DO MODELO 01 - Education Vídeo Tutorial.docx, Modelo 01.docx). O botão Roteiro aparece no fim, à direita, da barra do modelo (a linha que abre/fecha o modelo). Não precisa escrever nada no Word_Mestre.md.

2) Arquivo usado dentro de uma etapa (Excel, .skp, etc.)

Coloque o arquivo em downloads/ e, no Word_Mestre.md, escreva o nome do arquivo com a extensão entre colchetes, no fim da linha. Funciona em qualquer campo de texto, o mais comum é [OBJETO]:

[OBJETO]
Experimenter – “REPLICACOES_VALIDACOES”
Excel - "Modelo 10 - Validação Estatística" [Modelo 10 - Validação Estatística.xlsx]

A linha inteira vira um botão com ícone de download e a extensão (XLSX) ao lado. O que está entre colchetes não aparece no site, é só o nome real do arquivo na pasta downloads/.

Regras e cuidados

  • Extensões reconhecidas: xlsx xlsm xls csv skp docx doc pdf pptx ppt zip fsm txt.
  • O nome entre colchetes tem que ser idêntico ao do arquivo (acentos, espaços e maiúsculas). Se o arquivo não estiver na pasta, o relatório avisa: "Arquivo para download '...' nao encontrado".
  • Evite & e colchetes no nome do arquivo.
  • Tudo em downloads/ fica público no site. Não coloque gabaritos ou dados de alunos.
  • GitHub aceita arquivos de até 100 MB (avisa a partir de 50 MB).
  • Para atualizar um arquivo, basta substituí-lo na pasta (mesmo nome) e fazer Commit + Push.
  • Na impressão/PDF os botões viram texto simples e o botão de roteiro some.
